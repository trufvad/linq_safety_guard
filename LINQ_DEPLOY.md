# Запуск на ускорителе LinQ (сервер хакатона)

Ускоритель LinQ TPU доступен только на сервере хакатона: через **VPN** и **Jupyter** по адресу `hackathon.lin-q.ru` под логином команды. Значит, нейросеть должна работать там. Ниже два способа; основной — **А**.

| | Где интерфейс | Где нейросеть | Когда выбирать |
|---|---|---|---|
| **А. Всё на LinQ** | на сервере LinQ, открывается в браузере через прокси Jupyter | LinQ TPU | основной вариант для защиты |
| **Б. Интерфейс на ноутбуке** | на ноутбуке (`start.bat`) | LinQ TPU через маленький воркер | если на сервере нельзя поставить пакеты или прокси Jupyter не открывает порт 8000 |

В обоих случаях в правом верхнем углу интерфейса должно быть написано **«LinQ TPU»** (или «LinQ TPU (удалённо)»). Это и есть подтверждение для жюри, что инференс идёт на ускорителе.

---

## 0. Подготовка (один раз)

1. Подключите **OpenVPN** с конфигом хакатона.
2. Откройте `http://hackathon.lin-q.ru`, войдите под логином команды. Откроется Jupyter.
3. Проверьте ускоритель: **File → New → Terminal**, затем:
   ```bash
   python3 -c "import pytpu as tpu; print(tpu.Device.list_devices())"
   ls /dev/tpu*
   ```
   Должен напечататься список устройств, а не пустота и не ошибка.

## 1. Загрузить программу на сервер

1. В Jupyter слева кнопка **Upload** (стрелка вверх) → выберите `linq-safety-vision.zip`.
2. В терминале Jupyter:
   ```bash
   cd ~
   unzip -o linq-safety-vision.zip
   cd linq-safety-vision
   chmod +x start.sh
   ```

## 2. Вариант А: всё на LinQ

```bash
./start.sh linq
```

Скрипт:
- проверит `pytpu` и `/dev/tpu*`;
- поставит компоненты Python (первый раз 2–5 минут);
- запустит программу **строго на TPU** (`ENGINE=tpu`): если ускоритель недоступен, программа не уйдёт тихо на процессор, а сообщит об ошибке;
- напечатает ссылку вида `https://hackathon.lin-q.ru/user/<ЛОГИН>/proxy/8000/`.

Откройте эту ссылку в браузере на ноутбуке (VPN включён). Интерфейс работает через прокси Jupyter: видео, тревоги, загрузка роликов, зоны — всё как на ноутбуке.

Чтобы программа не остановилась при закрытии вкладки терминала:
```bash
nohup ./start.sh linq > linq.log 2>&1 &
tail -f linq.log          # посмотреть, что всё запустилось; выход — Ctrl+C (программа продолжит работать)
```
Остановить: `pkill -f "uvicorn app.main:app"`.

**Если ссылка `…/proxy/8000/` выдаёт 404**, значит, в Jupyter нет модуля `jupyter-server-proxy`. Варианты:
- поставить его: `pip install --user jupyter-server-proxy`, затем **File → Hub Control Panel → Stop My Server → Start My Server** и снова `./start.sh linq`;
- спросить экспертов LinQ, какой адрес или порт открыт для веб-сервиса;
- перейти на вариант Б.

**Если `pip` не может скачать пакеты** (на сервере нет интернета): на ноутбуке с интернетом соберите пакеты под Linux и ту же версию Python, что на сервере (её покажет `python3 --version` в терминале Jupyter; например 3.10 → `310`):
```bash
pip download -r backend/requirements.txt -d wheels --platform manylinux2014_x86_64 --python-version 310 --only-binary=:all:
```
Заархивируйте папку `wheels`, загрузите на сервер и распакуйте в `linq-safety-vision/wheels/`. `./start.sh linq` сам поставит пакеты оттуда, без интернета.

## 3. Вариант Б: интерфейс на ноутбуке, нейросеть на LinQ

На сервере LinQ (терминал Jupyter, в папке проекта):
```bash
nohup ./start.sh worker > worker.log 2>&1 &
cat worker.log            # здесь будет готовый REMOTE_URL
```
Воркеру нужны только `numpy` и `pytpu`: они на сервере уже есть, ставить ничего не нужно.

Токен Jupyter: **File → Hub Control Panel → Token → Request new API token**, скопируйте.

На ноутбуке в файле `.env` (в папке программы):
```env
ENGINE=remote
REMOTE_URL=https://hackathon.lin-q.ru/user/<ЛОГИН>/proxy/8500
REMOTE_TOKEN=<скопированный токен>
```
Перезапустите `start.bat`. В статусе должно появиться **«LinQ TPU (удалённо)»**. Каждый кадр уходит на ускоритель и возвращается обратно, поэтому FPS будет ниже, чем в варианте А: добавляется сеть через VPN.

## 4. Цифры для защиты: замер скорости на TPU

В терминале Jupyter, в папке проекта:
```bash
cd backend
ENGINE=tpu ../.venv/bin/python -m scripts.benchmark --image ../samples/bus.jpg --iters 200 --streams 1 2 4 8
```
Скрипт печатает время подготовки кадра, инференса на TPU и постобработки, FPS и задержку на 1, 2, 4 и 8 потоках, а также сколько камер тянет один ускоритель. Всё сохраняется в `benchmark_linq_tpu.json`. Для сравнения тот же замер на процессоре: `ENGINE=onnx`.

## 5. Проверка перед защитой

- [ ] в статусе интерфейса написано «LinQ TPU»;
- [ ] `curl -s localhost:8000/api/health` на сервере показывает `"engine": "linq_tpu"` и пустой `"warnings"`;
- [ ] загруженное видео показывает рамки людей, а тревоги приходят;
- [ ] сохранены цифры бенчмарка на TPU.
